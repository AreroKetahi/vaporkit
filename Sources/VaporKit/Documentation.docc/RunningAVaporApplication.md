# Migrate a Vapor Application Entry Point

Replace the entry point generated by the Vapor template with a declarative
``VaporApplication`` entry point.

## Overview

The Vapor template creates the environment, logging system, and `Application`
inside `Entrypoint.main()`. It then calls your `configure(_:)` function before
executing and shutting down the application.

`VaporApplication` performs the same startup sequence from a static
``VaporAppManifest``. Your application configuration remains ordinary Swift
code, while the executable also gains support for Argument Parser subcommands.
Vapor and ConsoleKit continue to interpret server arguments.

## Add Argument Parser

Add Swift Argument Parser to the executable target through VaporKit by using
the `VaporKit` product. You don't need to add Argument Parser as a direct
dependency unless application code imports it independently.

## Convert the Configure Function

The Vapor template provides a global function similar to this one:

```swift
func configure(_ application: Application) async throws {
    application.middleware.use(FileMiddleware(
        publicDirectory: application.directory.publicDirectory
    ))
    try routes(application)
}
```

Move its body into a type that conforms to ``VaporAppConfiguration``:

```swift
struct ServerConfiguration: VaporAppConfiguration {
    func configure(_ application: Application) async throws {
        application.middleware.use(FileMiddleware(
            publicDirectory: application.directory.publicDirectory
        ))
        try routes(application)
    }
}
```

Configuration values are immutable members of the manifest. They execute in
declaration order before the application lifecycle begins.

To register every router annotated for automatic discovery, include the
built-in configuration instead of calling `autoRegisterRouters()` yourself:

```swift
static let manifest = VaporAppManifest(
    configurations: [AutoRegisterRoutesConfiguration.default]
)
```

> Important: A configuration is responsible for cleaning up temporary work if
> it throws. Lifecycle handlers don't clean up an incomplete configuration
> phase.

## Replace the Template Entry Point

Remove the template's `Entrypoint.main()` implementation and declare an
`@main` type that conforms to ``VaporApplication``:

```swift
@main
struct MyServer: VaporApplication {
    static let commandName = "my-server"
    static let abstract = "Runs the MyServer API."
    static let version = "1.0.0"

    static let manifest = VaporAppManifest(
        configurations: [ServerConfiguration()]
    )
}
```

The `commandName`, `abstract`, `discussion`, and `version` properties customize
the root Argument Parser command. Omit them to use their defaults.

Don't retain both entry points. A Swift executable can contain only one
`@main` declaration.

Running the executable without an explicit subcommand starts the Vapor server:

```bash
swift run MyServer --env production serve \
  --hostname 0.0.0.0 \
  --port 8080
```

VaporKit passes these arguments through to Vapor. Existing ConsoleKit commands
and options therefore keep their original spelling and behavior.

## Observe the Application Lifecycle

Add a ``VaporAppLifecycleHandler`` when a resource belongs to the running
application rather than the configuration phase:

```swift
struct ServerLifecycle: VaporAppLifecycleHandler {
    func didBoot(_ application: Application) async throws {
        application.logger.info("Application started")
    }

    func shutdown(_ application: Application) async throws {
        application.logger.info("Application is shutting down")
    }
}
```

Include the handler in the manifest:

```swift
static let manifest = VaporAppManifest(
    configurations: [ServerConfiguration()],
    lifecycleHandlers: [ServerLifecycle()]
)
```

The manifest calls `willBoot(_:)` and `didBoot(_:)` in declaration order. It
calls `shutdown(_:)` in reverse declaration order.

## Add an Application Command

Expose application tools as Argument Parser commands without starting Vapor:

```swift
struct Diagnose: AsyncParsableCommand {
    func run() async throws {
        // Inspect the deployment without creating an Application.
    }
}

@main
struct MyServer: VaporApplication {
    static let manifest = VaporAppManifest(
        configurations: [ServerConfiguration()]
    )

    static let subcommands: [any ParsableCommand.Type] = [
        Diagnose.self
    ]
}
```

A custom command creates a Vapor `Application` only when the command's own
implementation explicitly creates one.
